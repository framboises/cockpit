## Indicateurs SAISON de la barre des jours (`saison_indicateurs.py`)

Sur la timeline **SAISON seulement** (main courante permanente du site, utilisee hors courses, ex. SSIAP), chaque jour de la barre de navigation repond d'un coup d'oeil a : le site est-il ouvert aux visites (libres / guidees) et quelle piste est utilisee (Bugatti, Maison Blanche, karting CIK / Alain Prost / Indy). Les epreuves gardent la barre historique (`_buildDayNav` appelle `_siTeardown()` hors SAISON).

- **Config GLOBALE** (pas par groupe), admin : `cockpit_settings {_id: "saison_indicateurs", indicators: [...]}`, liste ORDONNEE `{id, label, short (<= 4), color #RRGGBB, icon, rank "pill"|"dot", enabled, source}` ; `source` = `{type: "momentus_rooms", room_ids}` ou `{type: "visites", kind: "libre"|"guidee"}`. Semee une fois si absente (`$setOnInsert`, jamais d'ecrasement). Defauts : VL Visites libres (pastille #047857), VG Visites guidees (pastille #E69F00), BUG Piste Bugatti (room-833-A, #D55E00), MB Maison Blanche (room-834-A + 415/416/417-A, #0072B2), CIK (room-107-A, #7E3FBF), AP Alain Prost (room-108-A, #CC79A7), IND Indy (room-162-A, #E6C200). Palette Okabe-Ito ; la couleur n'est jamais seule (code court, position fixe, legende, infobulle).
- **Calcul** `compute(db, from, to)` : une requete `momentus_functions` + une `momentus_events` sur la fenetre, cache 90 s (vide a l'enregistrement de la config). Exclus : supprimes, annules, perdus, prospects (aussi refiltres en Python). ⚠️ **Les blackouts COMPTENT** (dates bloquees a la vente = epreuves, roulages : IAME sur les 3 karts du 04 au 11/10/2026), signales `blackout: true` ("bloque (blackout)" dans l'infobulle). Visites : `event_courant.saison_visit_days` (drapeau absent = autorise). Horaires : fonction si elle existe pour (evenement, espace, jour), sinon espace reserve ; debut seulement le premier jour, fin le dernier.
- **Routes** `saison_indicateurs_api.py` : `GET /api/saison/indicateurs?from=&to=` (user, 62 j max), `GET .../config` (user), `PUT .../config` (admin, CSRF ACTIF, validation stricte : 400 `configuration_invalide` + `details`), `GET .../rooms` (admin, espaces par site). Ni contactRoles ni montants.
- **Timeline** (`timeline.js`, bloc `SaisonInd` / `_si*`) : pastilles au-dessus du jour, points dessous a **position fixe** (un indicateur inactif garde un petit point gris), infobulle par indicateur (evenement, espace si plusieurs, horaires, reserve / option / bloque), legende repliable sous la barre (`#si-legend`, etat en localStorage `si_legend_open`). Clic sur pastille, point ou entree de legende : les vignettes de l'indicateur ressortent, les autres s'estompent (`.si-hit` / `.si-dim`), second clic ou bouton "Filtre" : retire. Correspondance : `momentus_event_id` + espace dans `place` (une vignette sans lieu suffit par l'evenement), vignette regroupee de blackouts par nom dans la remarque, visites par "au public" / "visite". Texte toujours en textContent.
- **Admin** : Configuration > "Indicateurs SAISON (timeline)" (`static/js/saison_indicateurs_admin.js`) : ordre, activation, libelles, couleur, icone, rang, source, selecteur d'espaces Momentus par site avec recherche, apercu, retour aux defauts (non enregistre tant qu'on ne sauve pas).
- Tests : `tests/test_saison_indicateurs.py`.

## Calendrier d'occupation (02/10/2026)

Bouton `calendar_month` colle a droite de la barre des jours (`#si-cal-btn`) : modale mois par mois (`_siOpenCal` dans `timeline.js`), meme route `/api/saison/indicateurs` sur le mois (cache 2 min par mois). Case = jour : pastilles en haut, une BANDE par indicateur 'point' en ordre fixe (couleur = occupee, gris = libre, hachuree = toutes les reservations du jour sont bloquees a la vente). Legende avec le nombre de jours occupes du mois. Survol / toucher : infobulle du jour. Fleches clavier, Echap, glisser gauche/droite sur telephone (plein ecran sous 600 px). Le mot 'blackout' n'apparait plus nulle part dans l'interface : 'bloque' / 'bloque a la vente'.

Legende : bouton `info` colle a gauche de la barre (`#si-legend-btn`), plus de ligne dediee ; infobulle cliquable pour filtrer ; filtre actif = bouton a la couleur de l'indicateur, clic pour le retirer.

## Seminaires du site (02/10/2026)

Bloc a part (pas un indicateur) : tous les seminaires Momentus du site, en METRIQUES, dans les cases du calendrier et dans l'infobulle du jour (barre des jours et calendrier).

- **Config** dans le meme document : `cockpit_settings{_id:"saison_indicateurs"}.seminaires = {enabled, types, max_list}`. Defauts : actif, types `Seminaire`, `Activites seminaires`, `Reception`, 5 evenements detailles. Ajoute a une config existante par `ensure_seed` (`$exists: false`, indicateurs jamais touches). Types compares NORMALISES (`norm_type` : casse, accents, espaces ; Momentus ecrit `Séminaire`, `Activités séminaires`, `Réception`). Validation `validate_seminaires` (30 types max, 60 car., `max_list` 1..20, au moins un type si actif). Admin : bloc "Seminaires du site" sous la liste des indicateurs (cases a cocher des types distincts de `momentus_events`, route admin `GET /api/saison/indicateurs/event-types`), enregistre par le meme PUT (`{indicators, seminaires}`, l'un ou l'autre ; CSRF actif).
- **Calcul** `compute_seminaires` (cache 90 s comme `days`) : evenements non annules / perdus / prospects / supprimes du type voulu, presents un jour s'ils ont un espace reserve ou une fonction AVEC espace ce jour-la (les notes a la journee sans espace donnent un effectif, pas une presence ; les dates de l'evenement sont une enveloppe). Effectif d'un evenement un jour : max des fonctions du jour (garanti > attendu > convenu), sinon `estimatedTotalAttendance` / `estimatedAttendance` ; 0 ou absent = inconnu (`None`, jamais invente). Horaires : plus tot / plus tard des fonctions du jour, sinon de l'espace reserve, vide = journee. Lieu : l'espace s'il est seul, sinon "N espaces".
- **Reponse** : cle a part `seminaires: {enabled, max_list, days: {jour: {count, pers, pers_unknown, items (liste complete depuis le 02/10, voir plus bas), more}}}` (jours sans seminaire absents) ; `days` inchange. Items tries par effectif decroissant : `{event, type, start, end, place, pers, status}`. Ni contactRoles ni montants.
- **Calendrier** : metrique `groups 8 · 639 p.` a droite du numero (meme ligne, hauteur de case inchangee ; >= 1000 : `1,3k p.`), seulement le nombre sur telephone. Legende : "Seminaires (nb · pers.) N j".
- **Infobulle** : bloc "Seminaires (N) - X pers." apres les pistes (heures, nom - lieu, effectif, option), puis "+ N autres" ; "connus" si des effectifs manquent.
- **Epinglage** (`SiTip` dans `timeline.js`, une seule infobulle partagee) : clic (ou toucher) sur une case du calendrier = infobulle EPINGLEE (defile, max 70vh, croix ; clic / toucher dehors ou Echap la ferme ; second clic sur la meme case aussi ; le survol d'autres cases ne la remplace pas ; Echap ferme l'infobulle avant le calendrier). Barre des jours : le clic choisit toujours le jour ; infobulle INTERACTIVE au survol (`pointer-events: auto`, masquage differe de 220 ms pour y entrer) avec un bouton epingle dans l'en-tete ; appui long tactile = epinglee. `_hideDayNavTooltip(true)` force la fermeture ; sans `true` (mouseleave) elle respecte l'epinglage et le delai. Placement : sous l'ancre, sinon au-dessus, sinon collee en bas.

Epreuves dans le calendrier : `saison_indicateurs.epreuves` (fenetres `event_courant.windows` + couleur / code de `evenement`), champ `epreuves` de la reponse. Barre continue par epreuve sur 2 voies fixes (au-dela '+N') : clair = montage / demontage, fonce = jours publics ; nom sur le premier jour et chaque lundi. Hauteur FIXE : 6 semaines toujours, cases de hauteur constante, legende de hauteur fixe (defile au-dela).

Seminaires : fusion par CLIENT et par jour (`accountId` Momentus, a defaut le nom d'evenement normalise) : une ligne, plage horaire elargie, espaces cumules ('N espaces'), effectif = le plus grand des reservations fusionnees (memes personnes, on n'additionne pas), libelle '<client> (N resa)'. Les reservations d'un meme evenement etaient deja une seule ligne. `count` = nombre de clients du jour.

## Liste depliable et programme d'un client (02/10/2026)

- **Liste COMPLETE** : `seminaires.days[jour].items` contient desormais TOUS les clients du jour (plus tronquee a `max_list`) ; `more` = `count - max_list` reste pour compatibilite. Le front montre `count - more` lignes (= `max_list`) et "+ N autres" (bouton) deplie / replie sur place (l'infobulle defile ; une infobulle de survol est epinglee au clic). Chaque item porte `client` (cle stable : `accountId`, a defaut `nom:<nom normalise>`, cf. `client_key`) et `account` (nom affiche).
- **Route** `GET /api/saison/client?client=<cle>&from=&to=` (user) -> `client_programme` : evenements du client de TOUS types (pas seulement les seminaires) hors annules / perdus / prospects / supprimes. Fenetre par defaut J-7 -> J+90, 180 jours au plus (`client_window` : 400 `periode_trop_longue` / `periode_invalide`) ; cle validee par `parse_client` (accountId `[A-Za-z0-9_.-]{1,80}` ou `nom:`, 400 `client_invalide`). Reponse `{client, account, from, to, events[{id, name, type, status, blackout}], days[{date, pers, items}], totals{days, events, max_pers}}` ; items `{kind: function|space, event_id, name, ftype, room, start, end, all_day, pers, phase}` : fonctions avec espace, espaces reserves SANS fonction ce jour-la (phase reserve / exploitation / demontage / bloque), fonctions sans espace (notes) seulement les jours ou l'evenement est present. Tri : fonctions puis espaces, journee entiere d'abord, puis heure. Projections explicites : jamais contactRoles, staff, e-mails, telephones, montants.
- **Front (programme)** (`SiProg`, `_siProg*` dans `timeline.js`) : ligne client cliquable (clavier Entree / Espace) dans l'infobulle du calendrier (epinglee) et de la barre des jours (survol interactif ou epinglee ; le clic l'epingle). Seconde fenetre "Programme <client>" a droite de l'infobulle, sinon a gauche ; telephone (<= 600 px) : panneau bas 64vh avec bouton retour. Jours groupes (en-tete date, jour clique en haut et souligne, jours passes estompes), lignes heures / nom / espace . type / effectif. Chargement, erreur avec "Reessayer", cache 2 min. Echap et clic hors des DEUX fenetres ferment d'abord le programme, puis l'infobulle, puis le calendrier ; second clic sur la meme ligne = ferme. Jour clique hors J-7..J+90 (calendrier lointain) : fenetre jour-14 -> jour+90. textContent uniquement.

## Recherche client / lieu sur toute la saison (02/10/2026)

- **Route** `GET /api/saison/search?q=&from=&to=` (user) -> `saison_indicateurs.search` (cache 90 s). Fenetre par defaut J-30 -> J+365, 400 jours au plus (`search_window` : 400 `periode_trop_longue` / `periode_invalide`) ; `q` normalise par `norm_query` (casse, accents, espaces, `<>"` retires ; 2 a 80 car., sinon 400 `requete_trop_courte`), compare en Python seulement, tous les mots doivent etre trouves. Un passage `momentus_functions` + un `momentus_events` (memes exclusions que les seminaires ; blackouts comptes, `blackout: true`).
- **Correspondances** : `client` = nom d'evenement, `accountName` ou type d'evenement ; `lieu` = nom d'un espace reserve (`bookedSpaces.roomName`) ou de l'espace d'une FONCTION ce jour-la (`matched`) ; `epreuve` = `saison_indicateurs.epreuves` (nom / code court, `phase` public / montage) ; `visite` = jours SAISON de visites si un mot commence par `visit` / `guid` ('es' ne remonte pas les visites). Presence d'un evenement un jour : comme les seminaires (espace reserve ou fonction AVEC espace). Fusion par (jour, client) : `{kind, label, client (cle de /api/saison/client), account, event, type, rooms (6 max), nrooms, matched, start, end, pers, reservations, status, blackout}`.
- **Reponse** `{q, from, to, days[{date, count, more, hits (20 max)}], summary{days, hits, first, next (premier jour >= aujourd'hui), by_month{YYYY-MM: nb jours}}, truncated}` ; 2 500 hits au plus (le resume reste complet). Projections explicites : jamais contactRoles, staff, e-mails, telephones, montants. ~160 ms sur titan_dev (8 900 fonctions).
- **Calendrier** (`SiCalQ`, `_siCal*` dans `timeline.js`) : champ dans l'en-tete (a droite ; telephone : ligne pleine largeur sous les fleches, toujours presente, police 16 px anti-zoom iOS). Debounce 280 ms, icone qui tourne pendant le chargement, cache 2 min par requete. Jours trouves : contour bleu (+ pastille du nombre si > 1), autres jours estompes (voisins compris) ; badge 'N jours ce mois' / 'aucun jour ce mois' / 'hors periode' a cote du titre ; fleches, clavier et glisser sautent au mois precedent / suivant qui a des resultats (fleche bleue). Liste en SURIMPRESSION (la modale garde sa hauteur) : a venir d'abord puis 'Jours passes', date, icone du type, libelle, compte · espaces · horaires · effectif ; clic = mois du jour + infobulle EPINGLEE ; bouton `event_note` = idem + fenetre 'Programme <client>'. L'infobulle du jour a un bloc 'Recherche' (lignes client / lieu cliquables -> programme). Echap : programme, infobulle, puis EFFACE la recherche, puis ferme. Fleches gauche / droite ignorees dans le champ ; Bas / Entree parcourent la liste.
- **Barre de recherche de la timeline** (`#timeline-search-input`) : indexe aussi `momentus_client` (nom du compte Momentus des vignettes SAISON) ; resultats rendus en textContent (plus d'innerHTML). SAISON + 2 car. : derniere ligne collante 'Chercher « q » sur toute la saison' -> `window.siOpenCalSearch(q)` (ouvre le calendrier, lance la recherche, va au mois du prochain jour trouve) ; Entree sans resultat local fait de meme. Epreuves : comportement inchange.
- Tests : `tests/test_saison_indicateurs.py` (`test_search_*`).

## Planning d'un client (05/10/2026)

Vue globale de ce que fait un client sur la journee (et les jours voisins), ouverte depuis la timeline.

- **Bouton** `view_timeline` "Planning" (title "Planning du client") sur toute vignette qui porte `momentus_event_id` (cartes `createEventItem` et lignes de regroupement `createClusterItem`, version icone seule) : SAISON et epreuves, jamais sur une vignette non Momentus ni sur le regroupement des dates bloquees. `stopPropagation` : n'ouvre ni le tiroir ni le depliage. Markup statique (`_plCardBtnHtml` / `_plWireCardBtn`).
- **Route** : `/api/saison/client` accepte `event=<momentus_event_id>` a la place de `client` (`parse_event_id` : `^event-\d{1,10}-[A-Za-z]{1,3}$`, sinon 400 `evenement_invalide` ; `client_for_event` -> `client_key` de l'evenement, inconnu = 404 `evenement_inconnu`). La vignette n'a donc pas besoin de la cle client (`momentus_client` = nom du compte, pas la cle). Meme reponse, memes projections (jamais contactRoles, staff, e-mails, telephones, montants). Fenetre demandee par le front : jour clique -7 -> +30, cache 2 min par URL.
- **Modale** (`SiPlan`, `siOpenPlanning(src, name, ds, opener)` dans `timeline.js`, aussi `window.siOpenPlanning`) : z-index 10050 (au-dessus du calendrier, de l'infobulle et du "Programme"). En-tete : nom du compte, types d'evenement, statut (confirme / option / N options, "bloque a la vente"), "jusqu'a N pers.", nb de reservations si > 1. Puces des jours de presence (Aujourd'hui / Demain / Hier marques) + "Plusieurs jours (N)". Jour clique sans activite : jour de presence le plus proche (a venir d'abord).
- **Vue jour** : resume (premiere -> derniere heure, nb d'espaces, effectif max), GRILLE horaire auto-ajustee (heures reelles +/- 1 h, 8 h mini, 0-24 h), une ligne par espace : espaces avec fonctions tries par premier usage, puis "Sans espace precise" (fonctions horodatees sans espace), puis espaces reserves sans creneau. Barres fines "journee" en haut de ligne ; blocs empiles en voies (jamais de texte superpose) : largeur visuelle mini 170 px (124 telephone) pour le texte, la duree REELLE est le trait en bas du bloc. Fonctions sur plusieurs jours : "17:30 ->" (finit le lendemain) / "-> 20:15" (commence la veille). Ligne rouge "maintenant" (mise a jour chaque minute) si le jour est aujourd'hui. Couleur = categorie (`_PL_CATS` : type de fonction Momentus s'il existe, sinon mots-cles du nom : Restauration, Montage / logistique, Visites, Piste / karting, Pleniere / ateliers, Autre ; espaces reserves hachures gris), legende sous la grille. Puis AGENDA (liste ordonnee : deroule, espaces reserves sans creneau, "Informations de l'evenement" = notes a la journee sans espace, repliees).
- **Vue plusieurs jours** : une ligne par jour (date, premiere -> derniere heure, nb d'espaces, effectif, 3 principales fonctions hors logistique, mini-frise sur une echelle commune) ; clic = vue jour.
- **Clavier / fermeture** : Echap (ecouteur `window` en capture, `stopImmediatePropagation` : ferme le planning SEUL, le programme / l'infobulle / le calendrier dessous restent), clic sur le fond, croix ; Tab piege dans la modale, focus rendu au bouton d'origine ; fleches gauche / droite = jour precedent / suivant (sauf dans la grille, qui defile). `_siTipKeys` et `_siTipOutside` ignorent tout tant que le planning est ouvert.
- **Telephone** (<= 600 px) : plein ecran (100dvh), bascule "Liste | Grille" (Liste par defaut, choix en localStorage `pl_phone_view`) ; la grille defile horizontalement dans son cadre, colonne des espaces collante, libelles "journee" qui suivent le defilement (`--sx`). Pas de debordement horizontal de la page.
- **Programme <client>** (`SiProg`) : bouton "Ouvrir le planning" sous le resume, ouvre la meme modale sur le jour d'origine.
